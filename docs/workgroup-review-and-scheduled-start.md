# 群组审核、代选与定时启动

## 审核同事

在“设置 → 工作群组”中先把 Mode 加入可委派同事，再从“审核同事”下拉框选择它。审核使用该 Mode 的角色定义、附加指令以及该 Mode 配置的默认 API 模型，不切换主程模型。当前审核请求是独立的单次模型调用，不会执行该 Mode 的工具、MCP 或 Skill；因此需要读取更多文件或调用工具才能判断的情况会保留人工审批。

群组的项目命令白名单优先生效。永久信任使用 V2 指纹，绑定项目、完整命令、实际工作目录的真实路径和可捕获脚本文件的真实路径及内容 SHA-256；旧版只绑定命令的记录保留但不再自动生效，用户可在白名单编辑器中查看和删除。无法捕获内容、含未捕获依赖或参数的命令不能加入永久信任；点击“完全信任”时会提示且不执行，需重新发起后选择单次允许。命令执行前的最终校验与操作系统执行之间仍存在竞态窗口。

未在白名单中的 Python/Node/PowerShell 简单内联代码或项目内脚本会交给审核模型，返回严格格式的允许/等待和理由；可识别的 bash/sh 和 Windows 批处理脚本、以及包含可能的导入、动态代码或参数等未捕获依赖的脚本，仍会发送可见代码给审核员，但无论其判断如何都等待人工。无法识别、读取或安全捕获的命令不调用模型，界面显示未审核原因并等待人工。审核状态、理由、可用的脚本路径和 SHA-256 会显示并保存在原命令消息旁。模型不确定、超时、错误、回复格式不正确或审核后脚本发生变化也会等待人工。自动允许只作用于当前操作，不写入永久信任白名单。

**安全边界：** 代码匹配只是保守筛选而不是完整的依赖分析，模型也可能判断错误。该功能不是操作系统沙箱，不能保证阻止联网、密钥访问或破坏性操作；对于不可信脚本和高风险操作应人工审查并使用隔离环境。不要把 Git 视为对未跟踪、忽略或工作区外文件的完整备份。

审核最多等待 60 秒，超时或出错保留原审批界面。模型不能覆盖已经作出的人工选择，切换群组或移除审核同事后迟到的结果也不会生效。模型的角色和附加指令必须与安全审核职责一致；模型并非安全沙箱。

## 本会话代选

聊天输入区勾选“本次会话由审核同事代答选择题”后，审核模型会看到有限长度的近期文字上下文、问题和选项。只有它返回严格有效的选项编号才会继续；不确定、超时、出错或选项涉及模式切换时仍等待用户。该设置随会话历史保存，每个新会话默认关闭。未启用时，追问不会再因为旧的自动审批配置而倒计时或默认选择第一项。

审核调用可能产生额外模型费用，当前调用不包含审核同事的工具和技能，也不计入主会话的模型用量统计。

## 定时启动

在新会话输入区填写任务，选择本地时间并点击“安排任务”。定时信息保存在当前 VS Code 工作区，可以取消；同一时间只保留一个待启动任务。启动前检查当前模式和 API 配置是否仍与安排时一致，不一致则停止并提示；本次会话代选选择会随任务保存。

已有会话的输入区也可以填写消息并选择“定时发送”，安排后不立即发送。回复绑定原会话；如果安排时正在等待回答某个问题，也会绑定该问题。到点时只有原会话仍在当前窗口、模式和模型未变，并且正在等待相应的普通对话回复时才发送；切换会话、问题已被回答、尚在执行或停在命令/工具审批时均不发送，也不会自动批准操作。发送失败或错过后可以点击“恢复内容”将文字和图片放回空输入框，再重新安排或手动发送。已有的已启动状态不会挡住下一轮的定时安排。

当会话显示“恢复任务”或 API 请求失败后的“重试”时，可以选择时间并点击“安排恢复”或“安排重试”，不需要输入消息，且不会发送或清空输入框里的草稿。定时操作绑定当前会话及当时的恢复/重试提示；到点时若提示已变化、会话已切换、模式或模型已改变，则不会继续，也不会批准其他工具或命令。重新打开会话后提示标识可能变化，需要重新安排。定时状态只表示恢复/重试动作已提交，不代表后续 API 请求一定成功。

需要保持 VS Code 与项目窗口打开，且到点时当前窗口中的项目没有活动会话，否则不会强行覆盖当前任务。不同 VS Code 窗口中的普通会话无法互相检测，请避免在其他窗口同时运行同一项目。重启后若错过时间不超过两分钟会尝试启动；超过两分钟则标记为错过，避免在预期的折扣时段之外意外运行。原子领取标记用于避免多个窗口重复启动同一定时任务；领取后如果进程异常退出，不会自动重试，请检查状态后手动重新安排。

## 历史图片

历史任务的图片引用优先从任务图片文件中读取并转为 Webview 可直接显示的数据地址，避免旧 Webview 资源 URI 失效导致缩略图破损。图片数据可能暂时增加扩展与 Webview 间的内存和消息传输开销。历史文件不存在或旧引用无法识别时不能自动恢复，需重新提供图片。

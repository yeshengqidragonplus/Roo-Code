# 工作群组实施状态

更新日期：2026-08-30

## 已完成

- 工作群组页支持创建、查看、改名/说明、维护同事名单和删除。
- `workgroup.colleagueSlugs` 为持久化配置；群组协调者不能委派未加入当前群组的 Mode。
- 创建工作群组类型 Mode 时会保存 `workgroup` 字段，避免只有 delegation 而无法被群组编辑器识别。
- 群组会话强制使用新的安全沙箱审批：旧 BRRR 自动审批控件隐藏，黄色盾牌常驻且不可关闭。
- 新审批中的命令使用项目级 SHA-256 精确白名单。用户可拒绝、允许一次或“完全信任”；完全信任保存至 `.roo/command-trust.json`，可从工作群组设置打开并删除条目。
- 普通 Mode 开启安全沙箱时也使用 SHA 白名单；关闭时继续使用 Roo 原审批逻辑。
- 群组顶部 API Profile 切换只作为当前群组主程任务的临时选择，不写入 Mode 默认模型绑定；被委派同事仍使用各自 Mode 的 `apiProfile`。
- 已增加命令白名单单元测试，覆盖精确匹配、项目隔离与删除。
- 工作群组可指定 `leadModeSlug`。运行群组时使用负责人 Mode 的角色提示词、默认模型、原生工具、Skill 与 MCP 权限；群组本身只补充可委派同事目录和协作规则。这样 Arthur 不必携带 Unity、Jenkins、知识库等专家工具定义。
- “模式配置”保留隐藏 Mode 的编辑入口；隐藏只影响聊天选择器，方便维护 Arthur 这类群组负责人。
- 模式编辑器新增“已分配 MCP”下拉多选。MCP 服务页始终列出全部服务；Mode 的选择仅控制其工具是否进入最终系统提示词。服务清单直接读取 MCP 配置，因此未连接或停用的服务仍可分配。
- MCP 服务器 `modes` 的语义：字段缺失 = 兼容旧行为，对所有带 `mcp` 工具组的 Mode 可见；非空数组 = 仅列出的 Mode；空数组 = 服务保留但暂不分配给任何 Mode。该规则同时在工具注入和执行侧守卫生效。
- `TOOL USE` 不再强制每轮调用工具：只有 Mode 具备已分配的工具组、MCP、Skill 或委派能力时才注入该协议。Mode 可选“按需调用”（默认）或“完成前必须取证”；策略只约束使用方式，不授予任何能力。
- Mode 的原生工具已由粗粒度工具组升级为可逐项选择的 `nativeToolNames` 白名单；未配置该字段的旧 Mode 保持原有整组权限。勾选项同时限制工具注入和运行期校验，MCP 仍按服务独立分配；会话完成、提问等基础生命周期工具保持系统必需、不可从此处关闭。
- `TOOL USE` 的注入以解析后的原生工具白名单为准：已迁移到 `nativeToolNames: []` 的 Mode 不会因遗留的工具组名称而收到工具协议；Skill、已分配 MCP 或委派能力仍会按需触发该协议。
- 模式配置页的下拉框只决定正在编辑的 Mode。群组运行时回传的负责人（如 Arthur）状态不会再覆盖用户刚选中的配置项；用户仍可通过该选择器触发正常的会话 Mode 切换。
- 战鼓工作室配置已校正：Arthur 保留 `command` 用于 Roslyn 验证，并继承项目 AGENTS、规则与记忆；群组同事名单不再包含负责人自身。辅助专家继续关闭这些项目上下文，避免无关 token 占用。
- Web Researcher 的浏览器 MCP 回退改为条件能力：只有实际分配了浏览器 MCP 时才使用，否则明确报告检索限制。

## 1. 出发点

痛点只有一句：**自动审批也一直弹窗打断人**。设计原则也只有一句——

> **审批的必要性与"不可逆 / 逃逸沙盒"成正比。凡是能撤销、且待在项目内的操作，审批就是纯摩擦，不该问。**

项目目录内有 git checkpoint 兜底（删改可回滚），所以项目内的读写不该问；项目外、或没见过的新命令才问。

## 2. 唯一决策点

所有审批都汇聚到一个函数：`src/core/auto-approval/index.ts` 的 `checkAutoApproval()`，对每个操作返回四选一：`approve` / `deny` / `ask` / `timeout`。本机制作为**零影响叠加层**加在它最前面：

```
checkAutoApproval:
  非阻塞 ask            → approve           （不变）
  会话模式 == sandbox   → checkSandboxApproval(...)   ← 新增分支
  否则                  → 原有 alwaysAllow* 逐类逻辑   （逐字不变）
```

**零影响保证**：会话模式不是 `sandbox`（含未设置）时，永不进入新分支，其余逻辑与打 tag 前完全一致。已由测试锁定（见 §5 的 "zero-impact" 用例）。

## 3. 三档会话模式

| 档位            | 含义                                           | 状态            |
| --------------- | ---------------------------------------------- | --------------- |
| **L0 手动**     | 现状：逐类 `alwaysAllow*` 开关决定，基本每步问 | 不动（默认）    |
| **L1 沙盒自治** | 项目内自动、项目外问、信任命令自动、追问永远等 | ✅ 后端已实现   |
| **L2 无人值守** | 过夜跑：项目外跳过记录、新命令套系统沙盒       | ⛔ 未做（以后） |

设置字段：`autoApprovalMode: "manual" | "sandbox"`（`packages/types/src/global-settings.ts`）。未设置 == manual。

## 4. 主表：什么情况 × 哪档 → 怎么处理

| 情况                               | L0 手动                    | **L1 沙盒（已实现）**                     | L2 无人值守（以后）  |
| ---------------------------------- | -------------------------- | ----------------------------------------- | -------------------- |
| 读文件 · 项目内                    | 问（除非开只读免批）       | **自动**                                  | 自动                 |
| 读文件 · 项目外                    | 问                         | **问**                                    | 记录后继续           |
| 写/改 · 项目内                     | 问（除非开写免批）         | **自动**（git 兜底）                      | 自动                 |
| 写/改 · 项目外                     | 问                         | **问**                                    | 跳过并记录           |
| 写 · 受保护文件（`.rooprotected`） | 问                         | **永远问**（红线）                        | 永远拒               |
| 删文件                             | 问                         | **走命令信任名单**（回收暂存未做，见 §7） | 自动+回收暂存        |
| 跑命令 · 信任名单                  | 自动（若开执行免批）       | **自动**（模式即启用，不需另开）          | 自动                 |
| 跑命令 · 新命令                    | 问                         | **问**                                    | 套系统沙盒跑 or 跳过 |
| 命令 · 拒绝名单                    | 拒                         | **拒**                                    | 拒                   |
| 调 MCP 工具                        | 按工具免批设置             | **按工具免批设置**（MCP 可逃逸，从严）    | 同左                 |
| 切模式 / 开子任务                  | 问（除非开）               | **自动**（低风险）                        | 自动                 |
| 追问（问题）                       | 问，**有倒计时自动选1** ⚠️ | **问，无限等**（无倒计时）                | 记录假设，继续       |
| 非阻塞 ask                         | 自动                       | 自动                                      | 自动                 |

## 5. 测试

`src/core/auto-approval/__tests__/index.spec.ts`（23 例，全绿）：

- **zero-impact 组**：无 state / 总开关关 / 只读免批 / 写免批 / 倒计时——证明 manual 模式逐字不变。
- **sandbox 组**：读写内外、受保护文件、命令信任/未知/拒绝、追问无倒计时、MCP 免批与否、切模式/子任务、todo/skill。

## 6. 待定：UI 入口（阻塞"能用起来"）

后端已通，但没有开关就打不开。放置方式是关键决策——**放错地方就会像工作流/专家面板一样成为没人用的旁路**（本项目最大教训）。候选：

- **A. 聊天输入框旁的档位切换**（Manual / Sandbox），会话开始时顺手一点——离"决策点"最近，最难被遗忘。推荐。
- B. 并入现有 AutoApproveDropdown（但它是逐类布尔开关体系，沙盒是"模式"，语义会打架）。
- C. 命令面板 / 设置项（最省事，但最容易被忘记 → 最可能沦为旁路）。

> 另注："会话级"目前用一个全局设置承载（习惯上每次开工手动切）。真正的 per-session 作用域是可选的后续增强，v1 不做。

## 7. 明确不做（本次）

- **删除回收暂存 + 红线名单机制**：删除的无条件自动放行依赖"挪进回收站可找回"，未做。当前删除仍走命令信任名单（未知 `rm` 会问），安全。想保护 git 忽略的不可再生文件（keystore/.env），把它们加进 `.rooprotected`。
- **L2 无人值守 / sandbox-exec 脚本围栏 / 独立系统用户**：均属"想让新命令都不弹、还想过夜跑"才需要，等 L1 用顺、且有真实过夜需求再说。（sandbox-exec 越界拦截与子进程遗传已在本机实测通过，结论存 dev-plan 讨论记录。）

# Mode、流程与工作群组的配置边界

## 两个入口的不同职责

聊天底部的运行选择器用于开始任务，因此可以选择三种运行形态：

- 普通 Mode：独立完成任务的角色。
- 流程：由工作流图约束执行步骤的运行形态。
- 工作群组：由协调者委派项目同事并汇总结果的运行形态。

设置页的“模式”只用于创建和编辑普通 Mode。流程应在“工作流”页管理，工作群组应在“工作群组”页管理；两者不能作为普通 Mode 混入模式配置列表。

## 每个 Mode 的模型

普通 Mode 在模式设置页通过“默认 API 配置（执行模型）”绑定 `apiProfile`。切换或委派到该 Mode 时会使用该 API 配置，且不会修改其他 Mode 的默认模型。

工作群组顶部的模型选择只是当前群组协调者任务的临时选择，不写入任何 Mode 的默认配置。群内同事优先使用各自的 `apiProfile`。

## 字段分层

模式设置页按用途分为三类：

- 系统提示词：角色与职责、补充指令；这些内容会拼接到模型的系统提示词。
- 用户可见信息：名称、简短说明、使用场景；用于用户识别与系统路由参考。
- 系统执行配置：默认 API 配置、工具权限；决定该 Mode 实际可使用的模型和工具。

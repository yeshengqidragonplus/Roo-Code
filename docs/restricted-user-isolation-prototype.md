# 受限用户隔离：验证原型

状态：**仅有独立诊断探针，系统隔离尚未实现。** 第三档是无系统隔离的“规则与评分审核”，不是本原型提供的受限用户隔离。现有安全审核档位也不提供系统级命令隔离。本原型不会创建账号、修改系统账户或文件权限，也不会执行 Git 推送。

目标是在 Windows 和 macOS 上分别为项目配置普通的受限系统用户，并在未来以该身份启动命令。实际隔离是否成立取决于系统用户、用户组、文件 ACL、凭据、网络、子进程和平台安全策略；切换账号本身不等于沙箱。原有 VS Code 和 MCP 服务仍可能以主用户运行，不受此探针约束。

## 诊断探针

`scripts/isolation-probe.mjs` 在**当前进程身份**下测试：

- 当前用户名是否等于期望值；直接启动的 Node 子进程是否报告相同用户名。
- 在项目目录创建、读取并删除一个随机命名的测试文件。
- 指定的项目外测试文件能否读取，以及指定的项目外目录能否创建测试文件；只有明确的权限拒绝才视为拒绝，路径不存在等错误不算通过。

由管理员或主用户事先准备一个**不含敏感信息**的项目外测试目录和测试文件。测试目录需要足够的路径遍历权限使探针可以定位目录，但应禁止该受限用户在目录内写入或读取测试文件。探针必须由受限用户启动，而不是由主用户启动后填写受限用户名。四个参数使用绝对路径：

```text
node scripts/isolation-probe.mjs <项目目录> <项目外测试目录> <项目外测试文件> <期望的受限用户名>
```

探针会输出 JSON；所有检查通过时退出码为 0，否则为 1。通过只代表这几次测试的结果，**不证明整个系统安全，也不代表第三档具备隔离能力**。探针不检查全部项目外路径、用户组、提权、符号链接、凭据、网络、间接子进程或 MCP，也不验证强制推送限制。运行之前请确认测试目录可安全创建、删除探针自己的随机文件。

运行探针本身的回归测试：`node --test scripts/isolation-probe.test.mjs`。

## 正式功能尚需完成

1. 分别设计 Windows/macOS 受限用户创建与进程启动方式、密钥管理和跨账户环境变量隔离；失败时禁止回退到主用户终端。
2. 配置并验证项目根目录、系统工具和用户组/ACL；不能递归修改用户现有文件权限而不明确告知。
3. 测试符号链接、子进程、网络和凭据等越界路径，并处理 VS Code 远程扩展运行的位置。
4. 对 Git 强推增加执行前防护；命令文本检查不能阻止脚本或其他 Git 客户端绕过。强推的可靠限制还需要服务端分支保护和不具备绕过权限的凭据。不能只凭客户端检查声称强推已被禁止。
5. 如未来加入隔离档位，完成模式/用户配置、取消/输出接入及自动化测试；只有确认隔离可用才允许该档自动运行。MCP 保持独立审核。
